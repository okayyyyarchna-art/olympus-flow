# Construct description.md

1. **D1 - Define one observable objective.** At the pin, name the affected public
   entry points and bounded supported domain. Inventory ordinary modes, saved forms,
   sibling paths, lifetimes and errors before choosing exclusions. Distinguish:
   outside this feature (no new behavior promised), preserve current behavior
   (measure it on base), and reject (an observable requirement). Silence alone is
   not an exclusion; an unreachable case needs evidence, not a decorative disclaimer.
2. **D2 - Write atomic obligations in the ledger.** Split independent verbs, kinds,
   conditions, quantifiers and effects. Record the exact expected observable, public
   grounding, permitted alternatives, planned assertion and a plausible partial
   implementation it rejects. Aim for roughly 5-8 coherent asks as a scope heuristic;
   do not merge obligations to manipulate a count. Platform extraction is variable.
3. **D3 - Establish difficulty and feasibility.** Trace a necessary invariant through
   real repository layers. Construct the smallest input separating a shallow design
   from the contract. Confirm the hard path can be implemented and tested with the
   real interfaces. Do not use ambiguity, missing tools, unrelated bugs or unstated
   performance limits as difficulty. Do not forecast rates from historical trap scores.
4. **D4 - Draft a concise maintainer work item.** Include the ask/symptom, essential
   scope, observable outcomes and necessary public names. Retain a clarifying example
   or exact output identity when necessary. Avoid private helper/algorithm directions,
   solver process instructions and excuses for incomplete behavior. Context must be
   true but need not become a separate test. Category follows the semantic change,
   not a regex on the opening sentence. Do not fabricate anecdotes or human errors.
5. **D5 - Resolve semantic reach.** Search code, docs, configuration, diagnostics,
   synonyms and callers for consequential terms. For each possible second reading,
   record one reachable input producing two different outputs. Check quantifiers,
   negation, pronouns, causal connectives and exclusion direction. Two independent
   readers see draft + base without the reference. Settle separators before lock;
   a hidden test or reference-only documentation cannot settle public meaning.
6. **D6 - Human final wording.** Give the owner the audited draft and compact facts.
   After their rewrite, compare every obligation and known counterexample, not only
   existing test cases. Recheck changed terms, scope, public names, category and word
   count. Report accidental semantic changes for the owner to correct in their words.
   Count with `re.split(r'[\s\-/]+', text)`: historical cap 400; use <=390 margin
   unless current platform instructions differ. No local script certifies AI detection,
   plagiarism, novelty, requirement-count acceptance or the description band.
7. **D7 - Lock exact bytes.** Record hash, base, category, meaning-diff disposition and
   planned test alignment. Every normative promise needs a feasible discriminator;
   every planned assertion needs visible grounding. Keep sample and final contract
   identical. Once locked, fix tests/solution within it. An owner-approved redesign
   creates a new lock and fresh solves; old patches remain diagnostic examples only.

## Pre-submit self-check, in priority order

| Gate | Evidence required |
|---|---|
| Auto Review description, T5/T7, S1 | D1-D7 closed; one reading per consequential clause; no mechanism dictates; final word count/category recorded; both directions of text/assertion mapping checked. |
| False pass | Every atomic promised effect, including preservation/rejection, has an assertion and a grounded discriminator. No promise was removed from grading to release a passer. |
| Solution Quality | Reference meets the full locked meaning, including ordinary supported variants; no caveat retrofitted to excuse a defect. |
| Task Quality | Each assertion can be derived by a solver from text + pinned repository; scope is coherent and implementation freedoms are explicit privately. Context is not overcounted as a new ask. |

If the locked text has irreducible output-changing ambiguity, stop local readiness
and present the concrete separator. Do not silently choose the reference's reading.
