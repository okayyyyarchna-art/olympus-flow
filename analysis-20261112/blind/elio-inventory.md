# Decision inventory: elio history / remembered selection follow rename and move

Repository: elio-fm/elio at 49889695. Requirement: "Back/Forward history and the remembered selection should follow
files and folders that I rename or move inside elio, instead of pointing at paths that no longer exist."

## State that must follow (what exists today)

- Back/Forward stacks: `DirectoryHistory { back, forward: Vec<HistoryEntry> }`, each entry `{ cwd, selected_path }`
  (src/file_browser/directory_loading.rs:22-32). In memory only; no saved file reads it (only callers:
  src/app/actions/directory.rs:229, src/app/actions/navigation.rs:364,379, src/file_browser/selection_navigation.rs:48-52).
- Remembered selection: `directory_view_memory: HashMap<PathBuf, DirectoryViewMemory { selected_path, scroll_row }>`,
  keyed by directory (src/file_browser/file_browser_state.rs:34, src/file_browser/directory_loading.rs:34-38,102-114).
- The only place history changes today is the snapshot-apply step (src/app/actions/directory.rs:229-233 calling
  src/file_browser/directory_loading.rs:116-150).
- History `cwd` values are canonical (src/app/actions/directory.rs:295); entry paths come from that cwd.

## Result

Wrong-by-default decisions:
1. K1 - src/duplicate_finder/duplicate_results.rs:176-179 exact-match follow; input: rename folder F->G with history/memory under `D/F/sub` -> exact match leaves descendants stale.
2. K4 - src/duplicate_finder/duplicate_results.rs:169-192 sequential pair application vs src/file_operations/editor_bulk_rename.rs:342 allowed swaps/chains; input: bulk rename A<->B with history in `D/A` -> sequential mapping returns `D/A` (wrong folder).
